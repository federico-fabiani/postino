# ADR-0001 — egui shell, isolated HTML renderer

- **Status:** accepted
- **Date:** 2026-10-23
- **Deciders:** project owner, implementation agent

## Context

The ArtCraft reference apps (PdfCraft, PhotoCraft) are pure Rust with egui/eframe on wgpu, no
webview and no JavaScript. That choice gives them instant startup, low memory, one language and a
small attack surface. They can make it because they write their own document renderer: PdfCraft
has a PDF renderer, PhotoCraft a compositor.

Postino's document format is HTML email. A faithful HTML/CSS renderer is a browser-sized project.
The alternatives were:

1. **Pure egui + a small HTML subset renderer.** Maximum coherence and lightness, but complex
   newsletters and transactional mail will render imperfectly.
2. **egui shell + an isolated webview for the body/composer preview.** Coherent with the suite
   everywhere except one surface; faithful HTML; one OS-provided engine.
3. **Tauri + React/Vue for the whole UI.** Fast to build, but abandons the suite's stack, adds
   TypeScript/npm and makes the app feel like a web app.

## Decision

Use **egui/eframe** for the shell. Keep HTML rendering behind a `BodyRenderer` trait.

- M0-M4 use a text/sanitized-subset renderer. Complex mail can open in the system browser.
- M5 may add an optional, sandboxed webview backend behind a feature flag.
- The webview is confined to the message body and preview. It has no JavaScript, no application
  IPC, a strict CSP, remote content blocked by default and a local protocol for attachments.
- No Tauri, no Electron, no Vue/React in the product.

## Consequences

- The app keeps the suite's startup, memory and single-language profile for everything except an
  optional body pane.
- The composer is a block editor in egui, not a Word-like freeform editor. Advanced users get an
  HTML source mode.
- Some HTML mail will look simpler until the webview backend ships. This is visible and documented,
  not hidden.
- The core stays UI-agnostic: a later toolkit could replace egui without touching `postino-core`.
- The decision is reversible at the seam: `BodyRenderer` and the operation registry are the only
  contracts the UI depends on.
