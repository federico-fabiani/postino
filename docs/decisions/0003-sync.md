# ADR-0003 — IMAP is the synchronization protocol

- **Status:** accepted
- **Date:** 2026-10-23

## Context

The product goal is: install Postino on two machines, and within minutes both see the same
received and sent mail. The temptation is to build a sync service or a custom protocol.

That would duplicate what IMAP already provides, require a server the user must trust, and make
Postino unable to coexist with Thunderbird, Apple Mail or a phone.

## Decision

The mail server is the source of truth. Postino keeps an encrypted local cache and an operation
log, and synchronizes with standard IMAP/SMTP.

- Discovery: RFC 6186 SRV, autoconfig, manual fallback.
- Push: IDLE where supported; polling (default 60 s) otherwise.
- Incremental sync: `UIDVALIDITY` + UID ranges; `CONDSTORE`/`QRESYNC` where available.
- Local intents are optimistic and queued in an outbox with idempotency keys; replay is safe.
- Sent mail is `APPEND`ed to the Sent folder, deduplicated by `Message-ID` when the provider also
  saves it.
- Drafts use a stable client `Message-ID` and revisions. IMAP has no atomic draft update, so two
  devices can briefly create two copies; Postino reconciles and documents the limit.
- Deletions never expunge silently. Trash is a move; expunge is explicit.
- No Postino sync server, no POP3 as the primary protocol, no Gmail API as the only path.

## Consequences

- Multi-device sync works with any standards-compliant provider, including Aruba, Fastmail, Gmail
  and corporate IMAP.
- The client inherits IMAP's limits: flags can race, drafts can duplicate, server search differs.
- Providers with proprietary labels (Gmail) need a mapping layer; labels become folders/virtual
  folders, with an optional native API later.
- The local cache is a cache, not a second mailbox. The user can delete it and resync.
